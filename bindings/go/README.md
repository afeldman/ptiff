# Go bindings for libptiff

Go bindings for [libptiff](../..), the C++ planetary-imaging format library.

**This is promoted SWIG output**, not a hand-written cgo wrapper (see the
["alles in SWIG" migration](../swig/README.md#planned-migration) decision,
2026-08-11): `bindings/go/ptiff` is regenerated from
[`bindings/swig/ptiff.i`](../swig/ptiff.i) by SWIG, targeting the same
language-agnostic C ABI every binding builds on
([`bindings/c`](../c), built as `libptiff_c`). It never compiles any C++
itself — the generated wrapper is plain C, bound only to the `extern "C"`
surface of `libptiff_c`.

```
bindings/c/                standalone C ABI binding (shared by all languages)
bindings/swig/              single source of truth: ptiff.i + typemaps.i + Makefile
                            (SWIG regenerates each language's promoted output
                            from here — see ../swig/README.md)

bindings/go/
  go.mod                   module github.com/crater/ptiff-go (hand-authored, tracked)
  CMakeLists.txt           regenerates ptiff/ via `make -C ../swig go`, registers ctest
  README.md
  ptiff/
    *_test.go              hand-written test suite (tracked)
    ptiff.go                generated by SWIG -- gitignored, never hand-edited
    ptiff_wrap.c             generated by SWIG -- gitignored, never hand-edited
    cgo_flags.go             generated -- gitignored, never hand-edited
```

## Architecture: C ABI shared by every binding

libptiff is C++23 with PIMPL types and heavy dependencies (fmt/spdlog). Rather
than have each language binding fight cgo/FFI against C++ directly, the project
keeps a single, curated `extern "C"` veneer in [`bindings/c`](../c). Because every
foreign-language runtime (Go cgo, Rust FFI, Python ctypes, Ruby Fiddle, SWIG's
own generated glue) can call a plain C ABI, `libptiff_c` is the **one source of
truth** all bindings build on:

```
            libptiff (C++23 core, fmt/spdlog)
                 │
                 ▼
        bindings/c → libptiff_c   (extern "C" veneer)
                 │
                 ▼
        bindings/swig → ptiff.i + typemaps.i   (one .i, three language targets)
                 │
      ┌──────────┼──────────┐
      ▼          ▼          ▼
     Go        Python      Ruby
 (promoted:  (bindings/  (bindings/
 this dir)    python)     ruby)
```

Rust stays on rust-bindgen (`bindings/rust`) — no SWIG Rust target.

## What the API looks like

This is the **raw C-ABI surface**, not the idiomatic Go API a hand-written
binding would give you: functions and types are named and shaped exactly as
SWIG emits them from `ptiff.i` — `Ptiff_image_create`, `PTIFF_PIXEL_UINT16`,
`Ptiff_image_descriptor` (a struct with public fields, not a builder), no
`error`-typed return values. This was a deliberate trade-off (see
[`bindings/swig/README.md`](../swig/README.md#planned-migration)): one
generated module maintained from one `.i` file, instead of three
independently hand-maintained idiomatic wrappers.

```go
package main

import (
    "fmt"
    "github.com/crater/ptiff-go/ptiff"
)

func main() {
    fmt.Println("ptiff", ptiff.Ptiff_runtime_version())
    fmt.Println("backends:", ptiff.Ptiff_backend_names())

    desc := ptiff.NewPtiff_image_descriptor()
    desc.SetWidth(640)
    desc.SetHeight(480)
    desc.SetPixel_type(int(ptiff.PTIFF_PIXEL_UINT16))
    desc.SetChannel_count(3)

    img := ptiff.Ptiff_image_create(desc)
    defer ptiff.Ptiff_image_destroy(img)
    fmt.Println(ptiff.Ptiff_image_width(img), "x", ptiff.Ptiff_image_height(img))
}
```

A NULL C pointer surfaces as a **non-nil Go interface wrapping a zero
`uintptr`** (`Struct_SS_ptiff_sink` etc. — SWIG's default Go opaque-handle
typemap), not `nil`. Check `handle.Swigcptr() == 0`, not `handle == nil` — see
`ptiff/sink_test.go` for the pattern; this bit the ported test suite itself
during the migration.

## Build requirements

- A **C++23** compiler (to build `libptiff`/`libptiff_c`, which the Go package
  links but never compiles itself) and **CMake ≥ 3.26**.
- **SWIG ≥ 4** on `PATH` (regenerates `ptiff/ptiff.go`/`ptiff_wrap.c`).
- **Go ≥ 1.21** with cgo enabled (`CGO_ENABLED=1`).
- `make` on `PATH` (drives the SWIG regeneration in
  [`bindings/swig/Makefile`](../swig/Makefile)).

## Building and testing

### Option A — via CMake (recommended)

Configure libptiff (as a **shared** library — see note below), enable the C and Go
bindings, build `libptiff_c`, then let CTest regenerate and test:

```bash
conan install . --output-folder=build --build=missing    # or use vcpkg
cmake -B build -S . \
  -DCMAKE_TOOLCHAIN_FILE=build/conan_toolchain.cmake \
  -DBUILD_SHARED_LIBS=ON \
  -DPTIFF_BUILD_C_BINDINGS=ON \
  -DPTIFF_BUILD_GO_BINDINGS=ON
cmake --build build --target ptiff_c
ctest --test-dir build -R ptiff_go_bindings --output-on-failure
```

`PTIFF_BUILD_GO_BINDINGS` implies `PTIFF_BUILD_C_BINDINGS`. This registers two
CTests: `ptiff_go_bindings_generate` runs `make -C bindings/swig go` with
`PTIFF_C_LIB_DIR` pointed at the current configuration's `libptiff_c` build
output (a CMake generator expression, so it always matches Debug/Release/...),
then `ptiff_go_bindings` runs `go test ./ptiff`.

### Option B — manual, via the SWIG Makefile directly

```bash
# Regenerate ptiff/{ptiff.go,ptiff_wrap.c,cgo_flags.go} against an installed
# prefix (cmake --install build --prefix /where/ever) or an in-tree build dir:
PTIFF_C_LIB_DIR=/where/ever/lib make -C bindings/swig go
# or: PKG_CONFIG_PATH=/where/ever/lib/pkgconfig make -C bindings/swig go

cd bindings/go
go test ./ptiff
```

> **Prefer a shared `libptiff`.** When built as a shared library
> (`-DBUILD_SHARED_LIBS=ON`), libptiff bundles its C++ dependencies and, crucially,
> the process-wide `BackendFactory` self-registration (which happens in static
> initializers) is fully visible across the FFI boundary —
> `Ptiff_backend_names()` returns all registered backends (`tiff, memory, pds4,
> isis, zarr, cloud, openexr`). Static archives dead-strip the unreferenced
> registration translation units, so `Ptiff_backend_names()` can come back empty.

## Idiomatic usage

The `ptiff` package exposes both the raw SWIG surface (`Ptiff_*` functions,
`Ptiff_*`/`PTIFF_*` structs and constants) and an idiomatic object layer
(`Image`, `Tile`, `Logger`, `Metadata`, `Camera`) that wraps it — the same
structure as the Python `src/ptiff/` package. Prefer the idiomatic types:

```go
// Read
img, err := ptiff.OpenImage("a.tif")
if err != nil { /* ... */ }
tile, err := img.ReadTile(0, 0)
img.Close()

// Write (with an optional persisted camera)
cam := ptiff.Camera{
    HasIntrinsics: true, FocalLengthX: 700.0, PrincipalX: 64.0, /* ... */
}
img, err := ptiff.CreateImage("out.tif", 32, 32, ptiff.PTIFF_PIXEL_UINT8,
    ptiff.CreateOptions{TileWidth: 16, TileHeight: 16, Camera: &cam})
img.WriteTile(0, 0, make([]byte, img.TileByteSize()))
img.Close()

// Metadata (no live handle)
m, err := ptiff.NewMetadata("a.tif")
m.Field("ptiff.camera.model") // => "pinhole", true

// Logger
log := ptiff.Logger{}
log.SetLevel(ptiff.LogError)
log.Error("boom")
```

## Layout in the consuming module

The binding ships as its own Go module rooted at `bindings/go/`. Consume it with a
`replace` directive until it is published:

```
require github.com/crater/ptiff-go v0.0.0
replace github.com/crater/ptiff-go => /path/to/crater/src/ptiff/bindings/go
```

## Status

Covers the same C ABI surface as the other bindings: version, error codes,
logger, backend registry, `Image`/`ImageDescriptor`, and tile read/write
(`ptiff_source_*`/`ptiff_sink_*`). Richer domain types (`Scene`, `Camera`,
`Metadata`, …) and the storage/I/O layer are still largely
`Error::NotImplemented` in libptiff and so have no C ABI surface to bind yet;
they will show up here automatically once `ptiff.i` picks them up.
