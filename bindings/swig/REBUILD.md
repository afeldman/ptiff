# Rebuilding the SWIG bindings

How to regenerate the SWIG-backed language bindings from the Rust C ABI
(`crates/ptiff-c`) after either (a) the ABI surface changed in
`crates/ptiff-c/src/*.rs`, or (b) `ptiff.i` / `typemaps.i` / the Makefile
changed.

## What this directory builds today

One `ptiff.i` drives **two active SWIG targets** — **Go** and **Ruby** (see
`README.md` → "Targets & layout"). **Python** and **Octave are NOT SWIG
targets** anymore: Python is bound natively with PyO3 (`crates/ptiff-python`),
and Octave via the hand-written C++ MEX adapter (`bindings/octave/mex`). This
file intentionally contains no Python/Octave SWIG steps.

A new language (e.g. Perl, Java, C#, Lua) is added by appending a language
guard block to `typemaps.i` and a `make <lang>` target to the Makefile — see
the "ADDING ANOTHER LANGUAGE" note at the top of `typemaps.i`.

## The single source of truth: cbindgen's `target/ptiff_c.h`

The C ABI's source of truth is the `extern "C"` declarations in
`crates/ptiff-c/src/`. `cargo build -p ptiff-c` runs cbindgen and emits one
consolidated header at `target/ptiff_c.h` (repo root, i.e. `../../target`
from this dir). SWIG cannot parse the `PTIFF_C_API` visibility macro in that
header, so `make` builds `real_inc/ptiff_c.h` as a sed-filtered copy (the
`#if defined(_WIN32)...` block is dropped, making `PTIFF_C_API` expand to
nothing). SWIG parses against `real_inc/`; the generated wrapper still compiles
the `%{...%}` block against the **real** `target/ptiff_c.h`, so struct layouts
and prototypes always come from the authoritative source.

`real_inc/` is a reproducible build artifact: regenerated by `make`, gitignored.

## Rebuilding

### 1. Make sure `libptiff_c` and `target/ptiff_c.h` are current

```bash
# from the repo root:
cargo build -p ptiff-c --release
```

This both (re)generates `target/ptiff_c.h` via cbindgen and produces
`libptiff_c.{dylib,so,a}` in `target/release/`. `make staticlib` inside
`bindings/swig` does the same if it is missing.

### 2. Regenerate + compile the SWIG outputs

```bash
cd bindings/swig
make go       # bindings/go/ptiff: ptiff.go + ptiff_wrap.c + cgo_flags.go
make ruby     # bindings/ruby/lib: ptiff_wrap.c -> ptiff.bundle
```

The `make all` target runs both. Each target regenerates `real_inc/` from
`target/ptiff_c.h` first (its `staticlib`/`$(GEN_DIR)` dependencies handle the
order automatically).

### 3. Run the promoted test suites

```bash
cd bindings/swig
make test     # go test ./... in bindings/go/ptiff, then the Ruby suite in bindings/ruby/test
```

or per language:

```bash
cd bindings/go/ptiff && go test ./...
cd bindings/ruby/test && RUBYLIB=$(abspath ../lib) ruby test_roundtrip.rb
```

## After an ABI change

Every time the `extern "C"` surface in `crates/ptiff-c/src/*.rs` changes:

1. `cargo build -p ptiff-c --release` regenerates `target/ptiff_c.h`.
2. `make -C bindings/swig go ruby` (or `make -C bindings/swig test`) rebuilds
   `real_inc/` and the Go/Ruby wrappers against it.
3. Run `make -C bindings/swig test` to confirm parity.

High-level bindings never touch the C header by hand; cbindgen is the only
generator.

## Environment notes

- `swig` — SWIG 4.x. Tested with 4.5.0 (macOS) and 4.2.0/4.0.x (CI).
- `go` — the Go toolchain, for `make go` / `go test ./...`.
- `ruby` — a Ruby with headers (`RbConfig rubyhdrdir`), for `make ruby`.
- `cc` — a C compiler for compiling the Ruby extension wrapper.
- `libptiff_c` — resolved from the Rust workspace `target/release` by default;
  override with `PTIFF_C_LIB_DIR` to point at another directory containing
  `libptiff_c.{dylib,so,a}`.
