# Ptiff.jl — Julia binding for PTIFF

A hand-written Julia binding for the **PTIFF** (Planetary TIFF) format that
drives the Rust core through its stable C ABI (`libptiff_c`), generated by
cbindgen from `crates/ptiff-c`.

Unlike the Octave binding — which needs a C++ MEX adapter because Octave has no
FFI call — **Julia calls `libptiff_c` directly** with the built-in `ccall`.
There is no C/C++/SWIG layer to build: the only runtime dependency is the Rust
shared library produced by `cargo build -p ptiff-c --release`.

```
Julia -> Ptiff.jl (ccall) -> C ABI (libptiff_c) -> Rust core
```

Requires **Julia >= 1.6**.

## Build

Build the C ABI library once from the repo root:

```bash
cargo build -p ptiff-c --release        # or: cargo build -p ptiff-c
```

There is nothing else to compile for Julia. Optionally run `make build` from
this directory to confirm the library is present:

```bash
make -C bindings/julia build
```

## Test

```bash
make -C bindings/julia test
```

or directly:

```bash
julia --project=bindings/julia bindings/julia/test/runtests.jl
```

Set `PTIFF_C_LIB_DIR` to point `Ptiff.libpath()` at a non-default location of
`libptiff_c` (otherwise it is resolved relative to this source file under
`<repo root>/target/release/`).

## Use

Load the module (the package `Project.toml` declares `Libdl`; `Ptiff` is
activated with `--project=bindings/julia`):

```julia
using Ptiff
```

Reading:

```julia
info = Ptiff.read_info("a.tif")        # width/height/pixel_type/tiles/compression
src  = Ptiff.open_source("a.tif")       # opaque source handle
si   = Ptiff.source_info(src)           # descriptor of the open source
tile = Ptiff.read_tile(src, col, row)   # Vector{UInt8} decoded samples
Ptiff.close_source(src)
```

Writing (tiled, single-channel UInt8):

```julia
sink = Ptiff.create_sink("out.tif", 32, 32, Ptiff.PTIFF_PIXEL_UINT8, 1;
                         tile_width=16, tile_height=16)
cols, rows, tbs = Ptiff.sink_info(sink)     # tile grid geometry
Ptiff.write_tile(sink, c, r, fill(UInt8(7), tbs))
Ptiff.close_sink(sink)                      # flush; only then readable
```

Inspection / metadata / camera / backends / version / logging:

```julia
meta = Ptiff.read_metadata("a.tif")     # flattened ptiff.<domain>.<name> pairs
cam  = Ptiff.read_camera("a.tif")       # intrinsics/extrinsics/projection
names = Ptiff.backends()                # registered decoding backends
v = Ptiff.version()                     # runtime (major, minor, patch)
Ptiff.logger_set_level(Ptiff.LogInfo)   # LogTrace=0 .. LogOff=6
Ptiff.logger_log(Ptiff.LogError, "boom")
```

## Covered API

Version + error-code / pixel-type / compression / log-level constants,
logging, the backend registry, image descriptor reads (`open_source` +
`source_info` + `read_info`), flattened metadata, structured camera
intrinsics/extrinsics/projection, and tile read/write (`PtiffSource` /
`PtiffSink`, `read_tile` / `write_tile`, `close_source` / `close_sink`). Errors
from the C ABI surface as [`Ptiff.PTIFFError`](@ref) exceptions carrying the
`ptiff_error_code` name. See `test/runtests.jl` for the full surface covered
by `make test`.

## Notes

- `Ptiff.libpath()` dlopens `libptiff_c` at module `__init__`, resolving it
  under `<repo root>/target/release/` by default (respecting
  `PTIFF_C_LIB_DIR`), mirroring the Octave MEX Makefile's convention.
- The Rust core is statically linked into `libptiff_c`, so
  `Ptiff.runtime_version() == Ptiff.compile_time_version()` always.
- This binding is built and exercised in CI by
  `.github/workflows/julia-bindings.yml`.
